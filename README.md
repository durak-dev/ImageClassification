# ImageClassification
Image classification project: data preparation (duplicate quarantine, train/val/test split, quality check + restoration), label audit with CLIP, and CNN training with Keras.

The dataset lives **inside this repository**. There is no external download.

## Data layout

```
data/
├── original/                  raw data, placed manually, never modified (committed to git)
│   ├── images/
│   └── labels/                labels.csv (filename, class_id, description) [+ optional per-image label files]
├── split_manifest.csv         generated: which file belongs to which split (commit it so everyone shares the split)
├── train/  val/  test/        generated by the notebook (git-ignored), each with:
│   ├── images/                raw copies of the images of that split
│   ├── labels/                labels.csv, labels_corrected.csv
│   └── images_corrected/      denoised / contrast / sharpened images
utils/funcs.py                 helper functions
Preprocessing.ipynb
requirements.txt
```

If your files are still in `data/images` and `data/labels.csv`, move them to `data/original/images` and `data/original/labels/labels.csv`.

## What the notebook does (in order)

1. **Hash** all raw images; every image with an identical twin is a duplicate and **all** its copies go to `train` (never to val/test).
2. **Split** the unique images 70/15/15 (stratified by class, two-step) **before** any preprocessing. Files are copied to `data/{split}/images` and `data/{split}/labels`.
3. **Quality check** (noise, blur, contrast) – thresholds are picked on `train` only.
4. **Restoration** reads `data/{split}/images` and writes `data/{split}/images_corrected`.
5. **CLIP label audit** on `train` + `val` (not `test`), then `labels_corrected.csv` per split.

The split is reproducible: it is stored in `data/split_manifest.csv` and reused on later runs. Delete that file only if you want a new split.

## Option A – Run locally (GPU or CPU)

1. Clone the repo and enter it:
   ```bash
   git clone https://github.com/durak-dev/ImageClassification.git
   cd ImageClassification
   ```
2. Create a virtual environment and activate it:
   ```bash
   python -m venv .venv
   # Windows:   .venv\Scripts\activate
   # Mac/Linux: source .venv/bin/activate
   ```
3. *(Only if you have an NVIDIA GPU)* install the CUDA build of PyTorch first, using the command for your CUDA version from <https://pytorch.org/get-started/locally/>. Otherwise skip this step; the CPU build is installed in step 4.
4. Install the dependencies:
   ```bash
   pip install -r requirements.txt
   ```
5. Make sure `data/original/` contains `images/` and `labels/` (it does after `git pull`).
6. Open `Preprocessing.ipynb` (Jupyter or VS Code, select the `.venv` kernel) and run the cells top to bottom.
   The "Imports and hardware" cell prints whether `cuda` or `cpu` is used.

## Option B – Run on Google Colab

1. Open Colab, then *File → Open notebook → GitHub* and enter `durak-dev/ImageClassification` (or upload `Preprocessing.ipynb`).
2. *(Optional)* *Runtime → Change runtime type → GPU* to speed up CLIP.
3. Run the cells top to bottom. The setup cell detects Colab and clones the repo into `/content/ImageClassification`. The split folders are recreated from `data/original` and `data/split_manifest.csv`, so you get exactly the same split as everyone else. Colab already has the required packages.

## Saving checkpoints to GitHub (Colab)

The Colab disk is wiped when the session ends. If GitHub credentials are configured, the notebook commits checkpoints (`checkpoints/df_fixed.csv`, `checkpoints/clip_results.csv`, corrected labels, split manifest) to GitHub instead of keeping them on the VM. Locally nothing is uploaded; checkpoints are plain files in `checkpoints/`.

1. Create a GitHub personal access token with write access to this repo (fine-grained token, permission *Contents: Read and write*).
2. Copy `.env.example` to `.env` and fill it in (`.env` is git-ignored – never commit it):
   ```
   GITHUB_TOKEN=<your token>
   GITHUB_REPO=durak-dev/ImageClassification
   GITHUB_BRANCH=checkpoints      # created automatically from the default branch
   ```
3. On Colab `.env` is not part of the clone. Either upload your `.env` into `/content/ImageClassification/`, or add `GITHUB_TOKEN`, `GITHUB_REPO` and `GITHUB_BRANCH` as Colab Secrets (key icon in the sidebar, enable notebook access).

The settings are read by `utils/config.py` (environment → `.env` → Colab Secrets); the upload/download code is in `utils/github_sync.py`. Uploads go to `GITHUB_BRANCH` (default `checkpoints`), not to `main`, so they never conflict with code changes; merge or cherry-pick from there when you want them on `main`.

## Notes

* `git pull` before you start so everyone uses the same `funcs.py`, data and split manifest.
* `data/train`, `data/val` and `data/test` are generated and git-ignored; do not commit them.
* Only exact duplicates (identical file bytes) are detected. Re-encoded or resized copies of the same picture have different hashes and are not caught.
* To train on the cleaned data: `load_splits(DATA_DIR, label_file=CORRECTED_LABELS_FILE, image_folder='images_corrected')`.
